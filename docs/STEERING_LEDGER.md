# 写入账本与操作点：Steer vector 的设计理论与界面进度图

> **一句话**：这一轮（`circuit_landscape_v1`）第一次把**原生单元的残差写入做成了可逐层精确记账的账本**
> （闭合相对误差 2.25e-07），这是本项目第一个不依赖梯度/归因近似的载体证据；
> 但它**没有把证据阶梯往上推一级**，而且**按当前页面的呈现方式读，会把效应量读大约 12 倍**
> （nats 口径 11.6×；绝对概率口径 7.4 亿倍）。
>
> 本文给出：① 这一轮实现的效果审计（数字全部标注来源）；② 一套指导 steer vector 的理论
> （**5 条公理** + 5 条设计规则 + 度量表）；③ 可视化界面的**有序进度图**（6 个阶段、门禁、依赖）。
>
> **§9 记录了第二轮的提升**：S0–S2 的实现、进度图面板、以及两套新判据。

## 1. 这一轮到底做了什么

### 1.1 实现内容

| 文件 | 作用 |
|---|---|
| `backend/core/circuit_trace.py` | 逐层挂 5 个 hook，导出残差写入账本：块入 / attention 写 / attention 后残差 / MLP 写 / 块出 |
| `backend/examples/collect_circuit_landscape.py` | 32 个 site × 6 个 arm 的采集器；导出 unit 级 gate/value/product/write |
| `frontend/components/CircuitLandscape.tsx` | 3D 景观 + 局部写入图 + 单元表 + 因果读数面板 |
| `experiments/circuit_landscape_v1/results/` | `circuit_landscape.json`（8.5 MB）+ `circuit_landscape.npz`（81 MB 审计档案） |
| `backend/examples/build_circuit_landscape.py` | **本次新增**：把 8.5 MB 原始导出裁成浏览器 payload，并生成进度图面板的数据 |
| `frontend/components/SteeringProgressMap.tsx` | **本次新增**：证据阶梯 × 作用对象二维地图 + S0–S5 阶段路线条 |
| `frontend/lib/steering-progress.ts` | **本次新增**：进度图面板的数据类型 |
| `backend/tests/test_circuit_landscape_build.py` | **本次新增**：读数带无缝平铺、分带不许混算、账本必须 32 site 聚合、"下一级"不许错位一级 |
| `backend/tests/test_circuit_landscape_panel.py` | **本次新增**：**源级**判据 C1–C9（不用渲染就能看出来的九类缺陷） |
| `experiments/circuit_landscape_v1/README.md` | **本次新增**：实验说明 + 复现顺序（此前这个实验没有 README） |

核心是 `circuit_trace.py:36-48` 挂的 5 个 hook 与 `:50-58` 的闭合恒等式：

```
h_out = h_in + attn_write + Σ_i a_i · d_i
```

以及 `collect_circuit_landscape.py:114-116` 的 6 个 arm：

| arm | 干预 |
|---|---|
| `baseline` | 无 |
| `plus` | +v，block 20 最后一个输入位置 |
| `minus` | −v，同上 |
| `random` | 同范数随机方向 |
| `block` | +v **且** 256 个冻结单元的 product 换成 baseline 的 product |
| `restore` | 无注入 **且** 256 个冻结单元的 product 换成 +v 的 product |

`block` / `restore` 的 product 替换发生在 down_proj 的**输入**（即原生单元的激活 a）上，
不是替换写入方向 d_i。因为 down_proj 是线性的，替换 a 的 32 个坐标
**精确等价于**让这 32 个单元按 donor 的激活去写残差 `[代码]`。语义正确。

### 1.2 实现审计：站得住的部分

**① 残差闭合是真的，而且有牙。** [代码+本轮]
`attn` 取 `block.self_attn` 的 forward 输出（Qwen3 里 o_proj 之后，即残差加数），
`mlp` 取 `block.mlp.down_proj` 的 forward 输出（即 Σ a_i d_i），
`out` 取 block 的 forward 输出。三者来自三个**互相独立**的模块，
所以"hook 抓错张量"会让闭合炸掉，而不是悄悄通过。
`circuit_trace.py:57` 的阈值 2e-5，本轮实测最大相对闭合误差 **2.25e-07** [本轮]，
即 float32 噪声量级。

我在 3 维投影空间里手算复核了 site 0 的 L20 与 L27，两处都精确到小数点后 4 位（残差 ≤ 5e-5）：
L20 baseline `in(218.6145,-75.3757,-146.7713) + attn(2.9349,46.8608,52.0115) + mlp(23.1122,12.7931,17.7869) = out(244.6615,-15.7218,-76.9730)` ✓
L27 baseline `in(205.7192,524.2807,-217.5815) + attn(64.6688,31.7795,-6.5897) + mlp(-2684.7654,-470.9537,-217.1753) = out(-2414.3774,85.1065,-441.3465)` ✓

**② 注入位置的重建是对的。** [代码]
`trace_forward` 的 `before` pre-hook 先注册，`native_forward` 的 `inject` pre-hook 后注册，
所以 `before` 看到的是**未注入**的残差；`row["input"] = incoming + α·v` 是事后重建。
闭合误差 2.25e-07 独立证明了这个重建正确——若 α、v 或位置错了，闭合会立刻失败。

**③ 剂量口径与 `neuron_mediation_v1` 一致。** [代码+本轮]
两个实验都是 `α = strength · ‖h_block20_input_last‖`，主剂量都是 0.1
（本轮 `collect_circuit_landscape.py:110`：`alpha = .1 * baseline["input_norm"]`）。
本轮 JSON 里逐 site 的 `alpha` 在 **48.8 – 79.3** 之间 [本轮]，反推 ‖h‖ ≈ **488 – 793**。
注意这是**相对**剂量：绝对注入量 `α` 本身在 site 之间差 **1.63 倍**。

**注入向量是单位向量** [代码]：`.cache/bpath/results_B/w_L19_m0.npy.json` 里
`"w_norm": 1.0`（B 路 `r6_rerun.py:270` 归一化后写出的），采集器直接 `np.load` 不再归一化
（只有 `random` 方向在 `collect_circuit_landscape.py:83` 被归一化）。
⇒ **注入范数恰好是 `0.1·‖h‖`，即残差范数的 10%**，"相对剂量"这个说法成立。
同一份 metadata 还记着 `layer: 20, npz_layer: 19`——
**向量抽自 block 20 的输出，注入在 block 20 的输入**（抽 L 输出、注 L 输入），
与本轮 `injection_layer = 20` 一致。

**④ native_forward 的 product 重建自检。** [代码]
`neuron_mediation.py:117-121` 断言 `effective_gate · value == a`（float32 容差内），
不通过直接抛错。所以导出的 `a` 与 gate/value 严格自洽。

**⑤ 导出字段的语义区分清楚。** [代码]
`product` = 实际使用的 product（patch 后），`natural_product` = 本 arm 自然的 product，
`raw_gate` = 激活前 gate，`gate` = SiLU(gate) = `effective_gate`。
UI 显示 `SiLU(g) × u = a` 用的是 natural 的三者，patch 后另起一行显示实际值——这一点是对的。

**⑥ 审计档案完整。** [本轮] 81 MB 的 npz 存了逐 site/arm 的 `incoming/input/after_attention/out`、
attention/mlp 写、每层 basis/mean、每层 down_proj 权重列。可离线复算任何账本结论。
**特别地**：`collect_circuit_landscape.py:163-164` 存进 npz 的 `attention`/`mlp`
是**未投影的 2048 维真值**（JSON 里的 `writes` 才是 3 维投影），
所以 §2.8 那张表可以**用真值范数重算**，而 32 site 的逐层聚合是**纯 CPU、不需要 GPU**。

**⑦ 导出的原生单元几乎全是"gate 为正"。** [本轮]
JSON 的每个 unit 带一个 `regime` 字段（= sign(gate) + sign(value)，
`collect_circuit_landscape.py:178`；负号是 U+2212）。16,344 个展示单元的分布是：

| regime | 含义 | 不在冻结组 | 在冻结组 | 合计 |
|---|---|---:|---:|---:|
| `++` | gate > 0, value > 0 | 7491 | 836 | **8327** |
| `+−` | gate > 0, value < 0 | 6880 | 976 | **7856** |
| `−+` | gate < 0, value > 0 | 49 | 9 | **58** |
| `−−` | gate < 0, value < 0 | 100 | 3 | **103** |

⇒ **99.0% 的展示单元 gate > 0**（16183/16344；冻结组里是 1812/1824 = 99.3%）。
由于 `a = SiLU(g)·u`，**这些单元的 product 符号由 value 向量决定，gate 只当幅度调制器**。
这给载体设计一个直接约束：**要改变残差写入的"方向"，得动 value 侧（`up_proj` / `down_proj`），
而不是靠翻 gate 的符号**——整个展示集合里只有 **161 个** gate 为负的单元。
⚠ 注意这是**展示集合**的统计（按 |product|·‖d_i‖ 与 |Δproduct|·‖d_i‖ 选出的 top-6∪top-6），
对全部 6144×8 个单元不成立。

### 1.3 实现审计：站不住或缺失的部分

**① 【critical】页面现在加载不出来。** [代码]
`CircuitLandscape.tsx:99` 取 `/latent/data/circuit_landscape.json`。
`frontend/public/latent/data/` 在 `.gitignore:123` 里，

该目录现在有 **41 个 json，唯独没有 `circuit_landscape.json`**。
**这一轮缺一个 build 脚本，页面必然 404。** 这是最先要补的东西。
（另外这条路由已经被挂进首页与另外 3 个页面的导航栏了，
所以点得到、进不去。）

> **状态更新（§9）**：build 脚本已经写好（`backend/examples/build_circuit_landscape.py`），
> 但**在跑过它之前，页面仍然 404**——因为 payload 是生成物，不是仓库里的文件。

**② 【major】8.5 MB 单文件直取。** [本轮]
`circuit_landscape.json` = 8,554,369 字节（8.5 MB），浏览器一次性 fetch + parse。
采集器其实**已经**裁过一次（`collect_circuit_landscape.py:199-202` 把 PCA 的 `mean`/`basis` 删掉，
只留 `explained_variance`），所以 8.5 MB 是**裁剪之后**的体积。
参照物：`readout_atlas.json` 7.3 MB（已是仓库最大）。这一轮还有 81 MB 的 npz 在同一目录外。
**剩下的 8.5 MB 主要在 `units` 数组**：32 site × 6 arm × 8 层 × **7–12 个**展示单元
（`displayed_native_units` 实际分布：7/8/9/10/11/12 各若干），每条带 `write`、`writer`
两个 3 维浮点数组（float32 全精度十进制展开，~20 字符/数）。
前端只需要：读数、state 投影、写投影、unit 表。
建议 build 脚本产出裁剪版（目标 < 1.5 MB）：浮点保留 4–5 位有效数字、
`writer` 由 `write` 与 `applied_product` 现算、或只导出 baseline/plus 两个 arm 的完整 unit 表。
原始 npz 留作审计。

**③ 【major】"剂量 0.1" 与旧产物不是同一个物理剂量。** [本轮+旧]
本轮 `strength 0.1` ⇒ α ≈ 48.8–79.3。
旧 B 路（`docs/BPATH_VECTOR_MECHANISM.md`）的 `rel 0.1` ⇒ α = 0.1 × 231.97767639160156 = **23.2**。
**同一个标签，物理剂量差 2.1–3.4 倍。**
本轮与 `neuron_mediation_v1` 同口径（可互比），与 B 路 / `steering_design` 的数字**不可直接比**。
再叠一层：框架 §2 的 L1 代价律只对 `s ≤ 0.2` 成立，而 s 是按 `rms(L)` 归一的；
本轮按 `‖h‖` 归一，要与那条律对齐必须先换算。这一点在产物里没有任何记录。
**第四层**：本轮的 `α` 随 site 的 ‖h‖ 变化（48.8–79.3，1.63 倍），
所以"同一剂量"在本轮**只能**是"同一**相对**剂量"。跨 site 比较效应量时，
绝对剂量差异是一个未被控制的协变量（见 §2.2）。

**④ 【major】随机对照只有 1 个方向。** [代码]
`collect_circuit_landscape.py:81-83`：`rng = default_rng(20261017)`，抽**一个**随机方向，
32 个 site 共用。`neuron_mediation_v1` 的 protocol 用的是 `random_directions: 4` [旧]，
框架 §1 明确要求"与**分布**比，不是与一个随机值比"，§8.6 给出规则
「n 个同范数随机臂只能否证超过经验分位数 n/(n+1)」——**n = 1 只能否证到 0.5 分位**。
按项目自己的尺子，这轮的**方向专属性最多只能说到"压过了 1 个随机方向"**，这是允许的最低限度。

**⑤ 【major】读数是 7 个 marker id 的**集合**概率，逐 marker 符号分裂未测。** [旧+代码]
`readout()` 是 `logsumexp(logits[MARKERS]) − logsumexp(all logits)`，MARKERS 有 7 个 id。
而 `docs/READOUT_ATLAS.md` 已经测出：7 个 marker 里**只有 7196 是正向读出**，
其余 6 个是负向，且最佳层各不相同 [旧]。
集合读数把 6 反 1 混在一起；这轮没有做 per-marker 分解。
更麻烦的是 `docs/NEURON_MEDIATION_RESULTS.md` 记录 B 路实测 **+w 压制 7196** [旧]，
而集合读数给出正值——**同一个向量在集合口径下看是正效应、在逐 marker 口径下可能是压制**。
这不是新发现的矛盾，但集合口径让它不可见。

**⑥ 【moderate】单元选择有选择偏差。** [代码+本轮]
`collect_circuit_landscape.py:156-158`：每个 (site, layer) 的展示单元 =
"baseline 的 |product|·‖d_i‖ 前 6" ∪ "+v 的 |Δproduct|·‖d_i‖ 前 6"。
**"响应最大的 6 个"按定义就是最大的**，所以表里的 `响应排序` 列是构造出来的，
不能当作"这几个单元重要"的证据。注释写了 "descriptive only, no behavior scores select these nodes"——
这句只说"没有用行为分选"，但读者仍会把它读成"这 12 个单元是这个位置的机制"。
UI 的小标题"该问题此刻实际激活的原生单元"比注释更强。

⚠ **更要命的是：那 256 个载体单元几乎不出现在这张表里。** [本轮]
展示单元共 16,344 条，其中 `in_frozen_group = true` 的只有 **1,824 条**；
按 (site, layer, arm) 平均是 **1.19 条/格**（每格展示 7–12 个单元、每层候选 32 个）。
⇒ **每层 32 个载体单元里，平均只有约 1 个会出现在用户看到的表里。**
UI 的单元表因此**不是**载体的视图（`in_frozen_group` 标记只出现在"选中单元"的详情栏，
表格行本身不标）。想看载体必须切到 `block`/`restore` 臂并逐行找"已替换"徽标。

**⑦ 【moderate】"其余 MLP 合计"在 UI 和 JSON 里是两个量。** [代码+本轮]
JSON `remainder` = 投影后的总 MLP 写 − **所有展示单元**的投影写之和
（每层 `total_native_units = 6144`，展示 7–12 个 ⇒ 剩下的是 **6132–6137 个**单元的贡献）。
UI `writeArrows` 的虚线箭头 = 投影后的总 MLP 写 − **当前选中那 1 个**单元的投影写。
同名不同义，读者会把 12 单元表和这条虚线当成同一件事的互补。

**⑧ 【moderate】3D 画的是投影长度，不是真值长度。** [代码+本轮]
表格里的 `‖写入‖` = |a_i|·‖d_i‖（**2048 维真值**）；
3D 箭头 = `basis@(d_i·a_i)`（**3 维投影**）。
每层 3 个 PC 只解释 **32.1%–33.3%** 的状态方差（L27 为 45.9%）[本轮]。
投影是收缩的，箭头长度系统性短于真值，且短多少取决于该方向与主成分的对齐。
**页脚写"h_out = h_input + attention + Σ aᵢdᵢ（浮点误差内）"是对的（2048 维），
但读者在 3D 图里看到的箭头之和并不等于图上那条状态变化。** 投影下的闭合确实精确成立
（投影是线性的），但视觉上"账本对不上"的印象来自"每个箭头短了一截"。

**⑨ 【moderate】L27 的 MLP 写主导一切，3D 景观会被它压扁。** [本轮]
site 0 baseline 的 3 维投影范数：L20 的 MLP 写 = 31.8，L27 = **2734**（86 倍），
L27 的 attention 写只有 72.4。L27 的块入投影范数 **603.8**，块出 2455.9——
**最后一个 block 的 MLP 写不是扰动残差，而是把残差整体改写**：
它的投影范数是块入的 **4.53 倍**（2734 / 604），且 PC1 分量与块入**反号**
（块入 +205.7 → MLP 写 −2684.8），PC2、PC3 同号。
这与"最后 block 做大幅 rescale"的已知结构一致，但页面把 L27 画成一条长箭头后，
其余 7 层会被压成一小团。

**⑩ 【minor】2D 视图不是等比投影。** [代码]
viewBox `-3.9 -3.65 7.8 7.3`，x:y ≈ 1.068，而 `scale()` 对三个轴用同一个 `extent`（数据等比），
所以数据在 viewBox 里是等比的，但 viewBox 本身非正方、容器又非定比，
最终 PC1/PC2 的像素比例与数据比例差约 6.8%。小的两维几何量（如"两个状态离多远"）不可直接读。

**⑪ 【minor】"展开当前写入"会重排整张图。** [代码]
`Plot` 的 `scale()` 把 `paths` 和 `arrows` 一起算 extent；勾选写入会改变 lo/hi/extent，
轨迹随之缩放跳变。

**⑫ 【minor】3D 坐标轴没有意义。** [代码]
`axesHelper args={[1]}` 是单位长度，而数据被缩放到 ±6；且 3D 没有 PC1/PC2/PC3 标签（2D 有）。

**⑬ 【minor】`aria-selected={unit.id === unit.id}` 是恒真。** [代码]
每一行都会显示为选中。应为 `u.id === unit.id`。

**⑭ 【minor】锚点位置与"marker 是下一个 token"的关系没有在页面上标出来。** [代码]
4 个 anchor site 的 baseline top-1 全部是 marker id（13824 / 10061 / 6771 / 10061）[本轮]，
这正是 anchor 位置可读的原因；页面只标了 "marker" 徽标，没解释为什么只有这 4 个可读。

## 2. 效果审计：这一轮**测到了什么**

下面全部是 [本轮]。

### 2.1 两个读数 regime（这是本轮最重要的发现）

32 个 site 的 baseline `marker_logprob` 分布是**双峰**的：

| regime | site 数 | baseline marker_logprob | baseline marker 集合概率 |
|---|---|---|---|
| **决策带**（anchor，marker 就是下一个 token） | 4 | −0.15 … −1.48 | 0.23 … 0.86 |
| **底噪带**（非 anchor） | 28 | −16.3 … −47.7 | ~1e-7 … ~1e-21 |

两端**绝不可混算**。而这一轮的第一个陷阱就是混算了。

### 2.2 效应量：混算 vs 分开

| arm | 全部 32 site 均值 | 4 个 anchor 均值 | 28 个非 anchor 均值 |
|---|---:|---:|---:|
| `plus` | **+1.6214** | **+0.1577** | +1.8305 |
| `minus` | **−1.1893** | **−0.3436** | −1.3101 |
| `random` | +0.0641 | −0.0080 | +0.0744 |
| `block`（+v 去掉载体） | +1.5747 | +0.1395 | +1.7797 |
| `restore`（载体 +v product 移植到 baseline） | +0.0350 | +0.0307 | +0.0356 |

符号一致性：`plus` 在 **32/32** site 为正，`minus` 在 **32/32** 为负。内部一致。

**关键对照（全部 32 site 求和，单位 1e-4）：**
- `plus` 合计 **+518861**，`minus` **−380566**，`random` **+20499**
- `blockEffect = plus − block` 合计 **+14955**，`restoreEffect = restore − baseline` 合计 **+11200**

**这一轮最要命的一句**：全部 32 site 的 `plus` 均值 +1.62 nats 看起来是个大效应，
但**它的 98.8% 来自底噪带**（28 个非 anchor site 合计 +51.25 nats，
4 个 anchor 合计只有 +0.63 nats；底噪带占 site 数的 87.5%，占效应量的 98.8%）。
而底噪带的 +1.83 nats 换算成概率是
`6.2e-11 → 1.78e-10`（site 0：baseline p=6.23e-11，plus p=1.78e-10）——
**一个真实但行为上无意义的尾概率变化**。

**同一个效应，两种口径：**

| | 决策带（4 site） | 底噪带（28 site） |
|---|---:|---:|
| ΔlogP（nats） | +0.158 | +1.831（**大 11.6 倍**） |
| Δp（绝对概率） | **+0.0862**（+8.6 个百分点） | ~+1.2e-10（site 0 为例；**小 7.4 亿倍**） |

**"最大的效应"是"最不可测的效应"。** 页面把两者画成同一种柱状图。

⚠ 还有一个未控制的协变量：本轮 `α = 0.1·‖h‖`，而 ‖h‖ 在 site 之间差 1.63 倍
（§1.3 ③）。**底噪带的 site 恰好拿到更小的绝对剂量**（最小 α = 48.8 出现在
site 18，其 baseline logP = −46.0，是最深的一个底噪点），
所以"底噪带效应更大"不是剂量更大造成的——它是在**更小**剂量下发生的。
这反而让"底噪带数字是概率尺度的产物"这一解释更可信。

### 2.3 决策带上的行为读数（4 个 anchor）

| site | base p | +v p | −v p | random p | block p | restore p |
|---|---:|---:|---:|---:|---:|---:|
| p06_think t=528 | 0.711 | 0.842 | 0.509 | 0.756 | 0.846 | 0.705 |
| p06_no_think t=372 | 0.228 | 0.297 | 0.152 | 0.209 | 0.281 | 0.245 |
| p07_think t=212 | 0.862 | 0.956 | 0.513 | 0.875 | 0.941 | 0.902 |
| p07_no_think t=322 | 0.523 | 0.574 | 0.465 | 0.512 | 0.570 | 0.529 |
| **均值** | **0.581** | **0.667** | **0.410** | **0.588** | **0.660** | **0.595** |

- `+v` 把 marker 集合概率抬高 **+8.6 个百分点**（相对 ×1.15）；
- `−v` 压低 **−17.1 个百分点**（相对 ×0.71）；
- **随机方向几乎不动**（+0.7 个百分点，2 正 2 负）；
- **载体只贡献总效应的一小部分**：按项目 `NEURON_MEDIATION_RESULTS.md` 的定义
  （阻断效应 = `+v` − `block`，恢复效应 = `restore` − `baseline`）：
  阻断效应 = +8.62 − 7.86 = **+0.76 pp**（占 +8.62 pp 的 **8.8%**），
  恢复效应 = **+1.45 pp**（**16.8%**）。
  按 `steering_design` 的记法 `compensation = (阻断 + 恢复)/2 = +1.1 pp`、
  `support = −1.1 pp`——相对总效应 +8.6 pp 都很小。

### 2.4 效应量 ≠ 可分辨度：把 `random` 臂当成噪声标尺

`random` 臂的**均值**（+0.064 nats）看起来很小，但它**逐 site 的散布**很大：
在 32 个 site 上 `random` 的 ΔlogP 落在 **−0.395 … +0.672**，**20 正 12 负**。
把这个散布当成这一读数的噪声标尺，得到的结论和直觉相反：

| | `+v` 的 ΔlogP 范围 | `random` 的 ΔlogP 范围 | 可分辨度 |
|---|---|---|---|
| 决策带（4 site） | +0.093 … +0.266 | −0.086 … +0.061 | **弱**（|Δ| 比值 2.8 / 3.1 / 7.1 / 4.4，几何均值 ≈ 4.0） |
| 底噪带（28 site） | +0.42 … +4.07 | −0.40 … +0.67 | **强**（+v 整体远离 0） |

⚠ **在行为上无意义的底噪带上，向量与随机方向反而最好分辨；
在真正有行为意义的决策带上反而最弱。**
这直接说明两件事：

1. **"效应量"和"可分辨度"是两个不同的量**，页面把两者画成同一种柱状图，
   于是既高估了底噪带数字的份量，又掩盖了决策带数字的脆弱。
2. **`n = 1` 的随机臂在决策带上根本不够用**。按框架 §8.6，
   1 个随机臂只能否证到 0.5 分位——它无法回答"决策带上的 +8.6 pp 是否超出随机方向"，
   只能回答"超出了**某一个**随机方向"。
   决策带 4 个 site 的 |+v| 都大于该 site 的 |random|（最小间隔 0.007 nats，
   site 29：0.093 vs 0.021），但 4 个样本、且 think / no_think 不是独立样本，
   **按项目自己的分母纪律，这里能报的只是"4/4 方向一致"，不能报 p 值。**

### 2.5 argmax 几乎不动（这一轮最反直觉的一条）

`+v` 在 32 个 site 里只改了 **3 个** 的 top-1 token（site idx 6 / 14 / 21），
新的 top-1 是 902 / 78064 / 752，**没有一个是 marker id**；
这 3 个 site **全在底噪带**。
在 4 个 anchor 上，`+v` 改 top-1 的次数是 **0/4**——因为那 4 个位置的 top-1 **本来就是 marker**。

逐 arm 的 top-1 改动数（同一份 JSON 直接数出来）：

| arm | 改 top-1 的 site | 新 top-1 | 说明 |
|---|---|---|---|
| `plus` | 3/32（idx 6, 14, 21） | 902, 78064, 752 | 全在底噪带，都不是 marker |
| `minus` | 1/32（idx 12） | 44364 | 唯一一次**把 marker 换成非 marker** |
| `random` | 2/32（idx 6, 12） | 902, 44364 | idx 6 给出的正是 `plus` 的新 top-1 |
| `block` | 2/32（idx 6, 14） | 902, 78064 | idx 6 / 14 与 `plus` **完全相同** |
| `restore` | **0/32** | — | 载体 product 移植**不改变任何一次 argmax** |

⇒ 3 个被 `+v` 改掉的 top-1 里，**idx 6 随机方向也能改出同样的结果**，
idx 14 只有 `block` 能复现，**只有 idx 21 是 `+v` 独有的**。
argmax 层面，`+v` 相对随机方向**没有可辨识的额外效果**（3/32 vs 2/32，且方向不唯一）。

⇒ **`+v` 在决策带上做的是"把已经是 marker 的 margin 加厚"，不是"把非 marker 换成 marker"。**
这直接决定了 §3 的 T2：载体问题必须问在 log-odds / margin 层面，不能问在 argmax 层面。

### 2.6 ±v 不对称：大部分是概率尺度，只剩 1.30 未解释

| 口径 | `+v` | `−v` | 比 \|minus\|/\|plus\| |
|---|---:|---:|---:|
| 全部 32 site，ΔlogP（nats） | +1.6214 | −1.1893 | 0.73（1.36 反过来） |
| 4 个 anchor，ΔlogP（nats） | +0.1578 | −0.3436 | **2.18** |
| 4 个 anchor，Δlog-odds（集合 p 的 log(p/(1−p))） | +0.6478 | −0.8432 | **1.30** |

逐 anchor 的 log-odds 位移：

| site | Δ log-odds `+v` | Δ log-odds `−v` | Δ log-odds `random` |
|---|---:|---:|---:|
| p06_think t=528 | +0.767 | −0.864 | +0.228 |
| p06_no_think t=372 | +0.360 | −0.497 | −0.110 |
| p07_think t=212 | +1.258 | −1.781 | +0.111 |
| p07_no_think t=322 | +0.206 | −0.230 | −0.044 |
| **均值** | **+0.648** | **−0.843** | **+0.046** |

⇒ **不对称的三分之二来自概率尺度**：在 nats 口径下 `−v` 强 2.18 倍，
换成 log-odds 后只剩 **1.30 倍**。这是因为读数是一个**集合概率**——
log-odds 把"集合 vs 集合外"这件事摆平了。
**剩下 1.30 倍没有解释**，两个候选来源：

1. **集合内部构成在变**。7 个 marker 的逐 marker 符号是分裂的
   （`docs/READOUT_ATLAS.md`：只有 7196 是正向读出，其余 6 个负向、最佳层各不相同）[旧]；
   集合概率的梯度是"各 marker 概率的加权平均"，注入会改变集合内部的权重，
   于是同一个 +v 在不同位点对不同 marker 的作用方向不同。
2. **向量本身对 logit 空间的响应非对称**（即 A_{v,α} 不是 −A_{−v,α}）。

预测（可证伪，见 §6 的 P2）：换成**单 token** 读数（那个具体的 marker）后，
不对称比应当降到 **≈1.0**；若仍显著大于 1，则来源 2 成立。

### 2.7 载体（256 冻结单元）的贡献：全样本 2.9%，决策带 11.6%

用项目自己的两个量（定义见 `docs/NEURON_MEDIATION_RESULTS.md`）：

- **阻断效应** = `+v` − `block`（把载体 product 钉回 baseline 后，+v 的效应少掉多少）= 载体的**边际**贡献；
- **恢复效应** = `restore` − `baseline`（只移植载体的 +v product）= 载体的**独立**贡献。

| 口径 | 阻断效应（边际） | 恢复效应（独立） |
|---|---:|---:|
| 全部 32 site | 14955/518861 = **2.9%** | 11200/518861 = **2.2%** |
| 4 个 anchor | 729/6309 = **11.6%** | 1226/6309 = **19.4%** |

（分母是同口径的总效应 `plus`；nats 口径与 Δp 口径的比值略有差别，
因为 softmax 的增益是 (1−p)，见 T1。）

按 `steering_design` 的记法 `compensation = (阻断 + 恢复)/2`、`support = −compensation`，
决策带上 compensation = **+1.1 pp**、support = **−1.1 pp**（Δp 口径，总效应 +8.6 pp）——
**两者都很小**。

**这是负结果，但它是干净且有价值的负结果**：这 256 个单元是在**乘法题**上按响应幅度选的
（`neuron_mediation_v1` protocol 的 discovery set，按"原生产品响应 × 写入列范数"排序，
没有用评估集的行为效应）[旧]，在本轮 AIME marker 读数上：
全部 32 site 只携带 **2–3%**，**决策带上也只有 9–19%**。
**载体身份是任务条件性的。** 这条负结果正好是 §3 T2 的直接证据。

### 2.9 一句话判决

- **账本做成了**：逐层逐单元精确记账，闭合 2.25e-07，可离线复算。这是本项目目前**最强的载体级工具**。
- **效应是真的，但很薄**：决策带上 `+v` 把 marker 集合概率抬高 **+8.6 pp**（相对 ×1.15），
  4/4 符号一致，**每次都压过了那一个随机方向**（|Δ| 比 2.8–7.1，几何均值 4.0）；
  但 `−v` 压得更多（−17.1 pp），argmax 一次都没换（0/4），载体只解释 9–17%，
  而这还只是"压过 1 个随机方向"——**不足以声称 L6**。
- **阶梯没动**：L6（"注入改变行为，且改变是这条方向特有的"）在这轮**只被部分触及**（有 random 臂但 n=1；读数是 token 概率不是自由生成行为），
  L7（概念 vs 位置 vs 格式）**完全没动**。B 路净位置仍是 L2 done / L5 missing / L6 partial / L7 不可判 [旧]。
- **呈现会误导**：把两个 regime 混在一个柱状图里，读者会得到一个大 12 倍的假效应；
  真实效应所在的决策带又恰好是**随机方向散布把它盖住**的地方（§2.4）。

### 3.2 五条公理

**T1（工作点函数性）操作点定理.**
一个 steer vector 没有内在的"效应大小"。对读数事件 R、在工作点 p（baseline 下 R 的概率），
被测到的 Δlog R 是 log-odds 位移的**非线性函数**；要把两个方向、两个位点的效应量放在一张表里比，
必须先换算到同一工作点。
　*依据*：softmax 的 log-prob 对 logit 位移的增益是 (1−p)；本轮两个 regime 的实测差 11.6 倍（§2.2）。
　*怎么测*：每次报效应量，同时报该 site 的 baseline p 与 regime。
　*什么会推翻它*：在**固定 baseline p** 下，测到不同方向的 Δlog R 与 log-odds 位移不成比例。

**T2（载体条件性）载体定理.**
原生单元的载体身份是 **(任务, 读数, 层, 剂量)** 的函数，不可跨任务搬运。
选择载体必须同时回答**充分性**（把该组单元的 +v product 移植到 baseline 能否复现效应）
与**必要性**（把该组单元钉回 baseline 能否消除效应）两问；
按"响应幅度"排序**不构成**载体证据。
　*依据*：本轮 256 冻结单元（乘法题选出）在 AIME marker 读数上只携带 2–3%
（全样本；**决策带上也只有 9–19%**）[本轮]；
`docs/NEURON_MEDIATION_RESULTS.md` 记录该组在乘法题上是**抵消者**（阻断 +0.048 / 恢复 +0.045，
而净效应是负的 −0.066）[旧]——**同一组在两个任务上角色相反**。
　*怎么测*：在**目标任务**上重选组，再做 block/restore 两问。
　*什么会推翻它*：在 AIME 上重选组后，决策带上的载体占比仍 < 20%
（现在用跨任务组是 11.6%）⇒ T2 错。

**T3（逐层可闭包）账本定理.**
残差写入账本在模型自身坐标下是**精确闭合**的（不闭合量 = float32 噪声）。
因此"注入的方向在第几层被写进残差、又在第几层被读出"是**可测量**的，且不依赖任何归因近似。
载体选择应当在**写入**发生的那一层做，而不是在行为读数端做。
　*依据*：闭合 2.25e-07 [本轮]；site 0 的相对扰动 15–17%（L20–L21）→ 2–3%（其后）[本轮，**单点**，32 site 聚合未算]。
　*怎么测*：用 npz 里的逐层 basis/mean + down_proj 列 + 写向量重算逐层相对扰动曲线。
　*什么会推翻它*：在 float64 下闭合误差不随精度下降（即闭合是恒等式之外的巧合）。

**T4（读数 regime）可测性定理.**
读数必须先声明 regime：
**底噪带**（p < 0.01）：Δlog R 是尾概率的统计量，**不得作为行为主张**，也不得与其它 regime 聚合；
**决策带**（0.05 < p < 0.95）：可作行为主张；
**天花板带**（p > 0.95）：饱和，须换读数。
本项目所有历史 marker 读数都必须按此重标。
　*依据*：本轮两 regime 的 Δlog 差 11.6 倍、Δp 差 7.4 亿倍 [本轮]。
　*怎么测*：每个 site 报 baseline p 与 regime。
　*什么会推翻它*：底噪带 site 的 Δlog R 在多次随机臂下**不**随随机方向变化
（则底噪带的数字其实是稳定的、可用的）。

**T5（可分辨度正交）噪声底定理.**
一个读数的**效应量**与**可分辨度**是两个**正交**的量：
效应量由方向与工作点决定；可分辨度由**该工作点上的噪声底**决定
（同位点、同剂量下换成一个无关方向，读数会动多少）。
⇒ **选读数不能只看"效应大不大"，必须同时看"噪声底多高"。**
一个**行为上毫无意义**的读数，可以同时具备"巨大的效应量"和"极低的可辨识价值"。
⚠ 注意别把这两件事混起来：**可分辨度高 ≠ 行为上有意义**。
底噪带的信噪比高，只是因为那里的一切都被放大成尾概率的相对变化（T4 仍然禁止把它当行为主张）。
　*依据*：本轮决策带上 |+v| / |random| = 2.8 / 3.1 / 7.1 / 4.4（几何均值 ≈ 4.0），
而底噪带上 `+v` 的 ΔlogP 高达 +4.07 nats、随机方向却只有 ±0.4——
**底噪带的信噪比反而是全表最高的** [本轮，§2.4]。
　*怎么测*：同一 site、同一剂量下跑 **≥4 个**同范数随机方向，报
　`|Δ(v)| / max|Δ(random)|` 与 `|Δ(v)| / p_{n/(n+1)}(|Δ(random)|)`（框架 §8.6 的分位规则）。
　*什么会推翻它*：把随机臂提到 ≥20 后，决策带的信噪比不降
（则随机方向的散布本身就是真实效应的一部分，而不是噪声）。

### 3.3 五条设计规则（这是"指导 steer vector"的落地部分）

**R1 · 先选读数，再选向量。**
在动手找方向之前，先确定读数事件 R 与其目标工作点。
若自然读数落在底噪带，**这个位点不产生可用效应量**——换位点、或换成逐 marker / 单 token 读数，
或者换行为级读数（任务正确率、生成质量）。
**不要**用"改向量"去救一个工作点选错的读数。
**并且**要同时量该位点的**噪声底**（换同范数无关方向，读数会动多少）：
工作点合格但噪声底也高的位点，同样是不可用的读数（T5）。

**R2 · 按两问选载体，不按响应幅度选。**
载体组必须在**目标任务**上重选，并同时给出：
充分性 = `restore` 复现的比例（**独立**贡献）；必要性 = `block` 消除的比例（**边际**贡献）。
**这两个量不是同一个数**，本轮决策带分别是 19.4% 与 11.6%——报告时必须分开写。
两者都要对**多个随机方向**报告（框架 §8.6：n 个同范数随机臂只能否证到 n/(n+1) 分位；n=1 无信息量）。

**R3 · 按写入发生层选注入层，并按 value 侧选载体。**
用账本先看目标行为对应的写入出现在第几层，再把注入点放在那一层附近；
用"目标行为读数在该层的写向量"与"该层实际被扰动的写向量"做对齐，而不是用下游 logit 相似度。
**并且**：因为 `a = SiLU(g)·u` 且 99% 的展示单元 gate > 0（§1.2 ⑦），
**要翻转写入方向就得动 value 侧**（`up_proj`/`down_proj` 的列），翻 gate 符号不是可行路径。
载体设计应当优先寻找"value 向量方向可控"的单元。

**R4 · 报"杠杆"，不报裸效应量。**
统一报 **杠杆 Γ = Δlog-odds(R) / 几何代价**，几何代价沿用框架 §2 的解析式
（`a = s·rms(L)/‖h‖`），并同时报 baseline p、regime 与**信噪比**。
**不同工作点的裸 Δlog R 不可比。**

**R5 · 成本项与增益项分开报。**
框架断言 ① 说"代价与方向无关"。本轮把它补完整：
一次干预的结果 = **代价项**（方向无关，几何破坏）+ **增益项**（方向相关）。
只报合并后的 Δlog R，等于把两个量混在一起；本轮 `random` 臂在底噪带的 +0.074 nats
就是代价项与增益项混合的可见后果。
⚠ 还要注意**均值会掩盖散布**：`random` 臂的均值只有 +0.064 nats，
但逐 site 是 −0.40 … +0.67（20 正 12 负）——**报均值就等于把噪声底报没了**。

### 3.4 度量表

| 度量 | 定义 | 怎么测 | 把住哪道门 |
|---|---|---|---|
| **工作点 p** | baseline 下读数事件的概率 | 读数处 log p → exp | T1 / T4；R1 |
| **regime** | floor (<0.01) / decision (0.05–0.95) / ceiling (>0.95) | 由 p 判定 | T4；R1；S1 |
| **杠杆 Γ** | Δlog-odds(R) / ½(a)² 形式的代价项 | 同时测 a = ‖αv‖/‖h‖ 与 log-odds 位移 | R4；T1 |
| **载体充分性** | `restore` 复现的 Δ / 完整 Δ | block/restore 两问，随机方向 ≥4 | T2；R2；S3 |
| **载体必要性** | `block` 消除的 Δ / 完整 Δ | 同上 | T2；R2；S3 |
| **写闭合残差** | ‖out − in − attn − Σ a_i d_i‖ / ‖out − in‖ | 现成，2.25e-07 | T3；S2 |
| **逐层相对扰动** | ‖Δ 写(layer)‖ / ‖写(layer)‖ | npz 逐层 basis 重算 | T3；R3；S2 |
| **载体迁移系数** | 在任务 B 上重选组、测得的载体占比 | block/restore ÷ 完整效应 | T2；S3 |
| **随机臂分位** | n 个同范数随机臂的经验分位 n/(n+1) | random arm 数量 | 框架 §8.6；S3 |
| **信噪比** | \|Δ(v)\| / max\|Δ(random)\|，以及 \|Δ(v)\| / p_{n/(n+1)}(\|Δ(random)\|) | 同 site、同剂量、≥4 个随机臂 | T5；R1；R4；S3 |

## 4. 证据阶梯上的位置

### 4.1 新增断言 ⑪

> **⑪ 跨位点的效应量不可比，除非工作点相同。**
> 只报裸 Δlog R 而不报 baseline p，等于把 1e-10 尾概率的相对变化和 0.7→0.84 的绝对变化放进同一列。
> 本轮实测：同一向量、同一（相对）剂量、同一读数，两种 regime 的 Δlog R 差 11.6 倍，Δp 差 7.4 亿倍。
> *逼出来的*：本轮 32 site 汇总的 `plus` 均值 +1.62 nats，**98.8% 来自底噪带**；只留 4 个决策带 site 后是 +0.158 nats。

- 但 random 臂 n=1（只能否证到 0.5 分位），且读数是"下一个 token 是 marker 的概率"，

  1 个随机方向也能改出同样的结果，**只有 1 个是 `+v` 独有的** [本轮，§2.5]。
- **决策带上的信噪比只有 2.8–7.1 倍**（|Δ(+v)| / |Δ(random)|，n=1），

L2′ 是本轮的**真正增量**：载体级证据第一次不依赖梯度近似。
但 L2′ 只是"能把写入算清楚"，**不等于**"知道哪几个单元承载行为效应"——那还需要 T2 的两问。

| P9 | 32 site 聚合的逐层相对扰动曲线与 site 0 同形（注入点 15–17%、其后 2–3%） | 聚合后注入点优势消失 ⇒ §2.8 是单点假象 |

## 7. 风险与未解决的问题

1. **n=4 的决策带。** 全部行为级结论只有 4 个 site，来自 2 道 AIME 25 题 × 2 模式。
   同一道题的 think / no_think 两条轨迹**不是独立样本**。
   按框架的分母纪律，这里能报的最强形式是"4/4 符号一致"，不能报 p 值。
   再叠一层：决策带上的 |+v| 只有随机方向的 2.8–7.1 倍，**且那是 n=1 的估计**（§2.4）。
2. **±v 不对称的机制未定。** §2.6 把不对称里约三分之二归给了概率尺度
   （nats 口径 2.18 → log-odds 口径 1.30），**剩下 1.30 没有解释**。
   两种可能：集合内部构成变化（7 个 marker 符号分裂，§1.3 ⑤）/ 向量本身的非对称。
   P2 可分辨，但需要新采集。
3. **载体集合的选择规则仍是"响应幅度"**，这正是 `neuron_mediation_v1` 已知会失败的那条 [旧]。
   真正的选择规则应当是因果效率（框架 §8.3 断言 ⑨ 附近与 `steering_design` 的下一步第 1–3 条都指向它），
   而**不是**本轮展示用的 top-6 响应排序。
4. **账本只到"写入"不到"读出"。** 精确记账能说清"哪个单元写了什么"，
   但"这个写入被读出端怎么放大"仍需下游雅可比——`docs/VECTOR_FUNCTION_THEORY.md` 的 G 度量是候选工具，
   尚未与写入账本接起来。
5. **历史数字的重新标注工作量。** 断言 ⑪ 一旦落地，`docs/` 里所有 marker 读数表
   （`NEURON_MEDIATION_RESULTS.md` / `REASONING_PATH.md` / `BPATH_*` / `READOUT_ATLAS.md`）
   都要按 regime 重标。**注意这会改动既有数字的读法，因此需要一次显式的版本化说明，而不是就地改写。**
6. **不要重跑的诱惑。** 本轮已经测到的东西不需要重跑：账本、闭合、regime 划分、载体迁移系数（对 AIME 而言）
   都已确定。下一轮采集只应针对 §6 的 P1/P2/P4/P5/P6/P8/P9。
7. **本轮最大的单点依赖：§2.8 的逐层表只有 site 0。** 32 site 聚合未算（P9），
   而它同时是 T3 的唯一经验依据。在聚合算出来之前，"相对扰动在注入点最大"只是单点观察。
