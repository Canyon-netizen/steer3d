Qwen3 隐空间观察台

从「模型为什么输出这个 token」到「加向量之后思维链变成什么样」——全部结论都来自实测，本页不含任何手写推测

三句话说清这个项目在做什么

大语言模型每写一个字，都是在几十万维的「隐向量」里做了一次运算，然后挑出得分最高的那个词。 这个项目想搞清楚两件事：它凭什么挑这个词而不是别的，以及我们往里加一个向量会发生什么。
71–83%token 的胜负在网络最后约四分之一处才定下来（不是开头！）
L12–L18干预最有效的层区间（43%–64% 深度）
~50 字加向量后，思维链在第一句左右就分道扬镳

三个反直觉的发现

① 「看得见决策」≠「干预最有效」

我们原本预测：既然 token 的选择在第 20 层左右定下来，那往第 20 层加向量应该最管用。 实测恰好相反：第 8 层加向量比第 26 层更有效（配对 t=3.01，24 题）。见 第 ④ 屏。

② 「接近随机」这个直觉是错的

第 0 层的「选中正确答案」比例是 56%，看起来像抛硬币。 但我们实测了随机对照（把备选词换成随机词），发现随机对照本身就有 78%——因为随机词的分数天生就低，输得很稳定。 所以第 0 层其实是比随机还差 23 个百分点，它在「积极地预测错」。见 第 ③ 屏。

③ 「94% 一致率」是短文本带来的错觉

本项目早期报告「干预后 94% 的 token 没变」，那是在只生成 60 个 token 时测的。 同样剂量、同样题目，生成 1024 个 token 时一致率变成 99.5%，输出分布差异从 0.136 掉到 0.0005。 原因很简单：开头的「好的、那么」这种词本来就不确定，占的比例又高。见 第 ⑤ 屏。

怎么用这个页面

每一屏都有可交互的部分：② 可以逐题逐 token 看候选词和它们随层数变化的分数； ③ 可以切换三个模型；④ 鼠标悬停每层看详细数字；⑤ 可以左右对照干预前后的思维链原文。

所有数字都从实验产物直接读出，页面上没有手写的总结数字。

为什么模型输出这个 token，而不是那个？

模型在每一步都要给词表里的 15 万个词打分。我们把这一瞬间的「隐向量」拿到网络中间某一层， 接上最后一层运算，看看如果只看这一层，它会选哪个词。这叫 logit lens（对数透镜）。 把这条曲线画出来，就能看到选择是在哪一层翻盘的。
■ 实线 = 真实计算结果； 虚线 = 随机对照（把备选词换成随机词时的同一曲线）。 灰底是「透镜不可信」区：此时该层的读出与模型真实输出差得太远，曲线本身说明不了什么。
怎么读这张图？
横轴是网络深度（层号），纵轴是「这个候选词比第一个候选词低多少」。 0 表示两者打平，负数表示它输得更少、更接近获胜。
曲线从负值区域冲上来、穿过 0 的那一刻，就是「选择被翻过来」的层。 越早穿过 0，说明这一层越早就已经决定了答案。

决策是在第几层定下来的？

上面的曲线是单步的。这一屏把 288 步叠在一起，看整体规律： 每个层「猜中最终答案」的比例。这是一个可以跨模型比较的指标。

为什么必须要有「随机对照」这条虚线？

我们最初把 50% 当作「完全瞎猜」的基准，写进了文档。后来实测发现这是错的。

把备选词换成随机词再跑一遍，结果是：第 0 层就有 — 的「一致率」，第 24 层就 100%。

原因：随机词的分数天生就极低，它「输」得非常稳定。 所以真正的基准不是 50%，而是这条虚线。真实曲线在虚线之上才是有效信息。 这也是本项目第三次因为「不给基线就解读数字」而修正结论。

干预往哪一层加最有效？（本项目最反直觉的一屏）

我们把同一个方向的向量分别注入到 8 个不同的层，每一处都取「该层状态大小的 20%」， 这样没有哪一层被少给了剂量。24 道题，每道跑两种条件。

第 ③ 屏说决策在 71% 深度定下来，我们据此预测「往深层加向量更有效」。实测方向相反：

诚实交代三件事：
1. 这不是「L16 一个尖峰」，而是 L12–L18 一整片平台——L16 与 L12 的 t=1.45、与 L18 的 t=0.53， 在 24 题下都不可区分。只有平台的边缘才分得开。
2. 三个指标峰值位置不一致：分布偏移和 token 一致率峰值在 L16， 而「有多少题出现 token 分叉」峰值在 L18–L20。我们没有挑好看的那个。
3. 深层失效不是剂量太小造成的：第 26 层的绝对向量是第 16 层的 12.1 倍， 效果反而小 5.6 倍——更大的扰动做更小的事，说明此时已经没有计算可以把它转化成不同答案了。 但第 8 层「较弱」这一点与剂量混淆（它的绝对量只有 L16 的 1/4.4），本实验分不开。

「94% 一致率」是怎么来的？——文本长度的陷阱

  

    
同一个剂量、同一批题，只改生成长度：

    

    

      这张表推翻的是本项目早期反复引用的那个数字。60 个 token 时，一致率 0.94、分布偏移 0.136；
      1024 个 token 时变成 0.995 和 0.0005。

      原因：开头的「好的 / 那么」这类词本来就不确定，而 60 个 token 里它们占比很高；
      生成到几百个 token 后，绝大多数是在续写已经确定的推理，扰动自然翻不动它们。

      所以「干预改变了 6% 的 token」这句话只在短生成下成立，换成长生成就变成 0.5%。
      引用效应量时必须同时说生成长度。
